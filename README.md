
# АРХИТЕКТУРА И ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ ВЕБ-ПЛАТФОРМЫ «ДОЛГ»

## 1. Общие сведения и назначение системы
Веб-платформа «ДОЛГ» представляет собой комплексное программное решение, разработанное в рамках ВКР. Система объединяет в едином рабочем пространстве интернет-магазин радиоэлектронных компонентов (РЭБ), интерактивный редактор принципиальных схем и SPICE-симулятор. Платформа ориентирована на автоматизацию процессов проектирования, верификации схемных решений и комплектации изделий, предоставляя инструменты инженерной аналитики, корпоративного взаимодействия и интеллектуальной поддержки проектировщика.

## 2. Технологический стек
Архитектура системы построена с использованием современных технологий, разделенных на следующие уровни:

*   **Backend:** Python 3.14+, Django 6.0 (паттерн MVT, ORM, встроенная административная панель).
*   **Frontend:** HTML5, CSS3, Vanilla JS (ES6+). Серверный рендеринг посредством Django-шаблонов; клиентские приложения на JS для редактора схем и симулятора.
*   **Графический движок:** HTML5 Canvas 2D (рендеринг схем, CAD, графики симуляции).
*   **Математическое ядро и симуляция:** 
    *   `ngspice.wasm` (Emscripten 2.0.7, ngspice 33) — выполнение SPICE-симуляций непосредственно в браузере через Web Worker.
    *   JS-MNA fallback — резервный решатель методом узловых потенциалов (MNA) на стороне клиента.
*   **Научная аналитика (Scientific Stack):** NumPy, SciPy, Matplotlib, Pandas (FFT-спектр, диаграммы Боде, анализ Монте-Карло, расчет THD/SINAD/ENOB, параметрический sweep).
*   **Графы, топология и символьные вычисления:** NetworkX (анализ связности и DRC), SymPy (символьные формулы), Schemdraw (генерация SVG-иллюстраций).
*   **Экспертные системы и ограничения:** `jsonschema`, `rule-engine`, Pint (валидация единиц измерения), Lark (парсинг SPICE/LTspice), Z3 (решатель ограничений для подбора номиналов), `scikit-fuzzy` (нечеткая оценка рисков).
*   **Машинное обучение и поиск:** `scikit-learn` (TF-IDF, косинусное сходство), PyTorch (Tiny Neural Backend для вероятностных подсказок).
*   **Базы данных:** SQLite (среда разработки), PostgreSQL (продакшен).
*   **Realtime-коммуникации:** Django Channels, Daphne (ASGI), WebSocket.

## 3. Компонентная архитектура (Структура Django-приложений)
Система реализована в виде модульного Django-проекта (`DOLG_Diploma`), включающего следующие изолированные приложения:

1.  **`Dolg_APP`** — ядро платформы: редактор схем, CAD, проекты, симуляция, AI-ассистент, ML-пайплайны, биллинг, Enterprise-функции (RBAC, аудит, SSO).
2.  **`shop`** — каталог товаров, корзина, формирование BOM (Bill of Materials), генерация PDF-документов (гарантийные талоны).
3.  **`accounts`** — управление пользователями, профилями, адресами (с использованием сигналов для автоматического создания `UserProfile`).
4.  **`orders`** — обработка заказов, логистика, интеграция с платежными шлюзами.
5.  **`knowledge`** — база знаний (энциклопедия), инженерная лаборатория, практикум обучения, корпус легальных источников.

## 4. Архитектура ключевых подсистем

### 4.1. Торговая платформа и управление каталогом
*   **Интеллектуальный поиск:** Гибридная система поиска. Базовый уровень использует `rapidfuzz` (multi-token parsing, fuzzy fallback для опечаток, facets с подсчетом). Продвинутый уровень (Phase 2) внедряет семантический поиск на базе TF-IDF (`scikit-learn`) с русской лемматизацией (`pymorphy3`) и Reciprocal Rank Fusion (RRF).
*   **Media Quality Gate:** Подсистема контроля качества изображений на базе `Pillow` и `ImageHash`. Осуществляет проверку на битость, минимальный размер, однотонность, вычисление perceptual hash для исключения дублей и генерацию процедурных PNG-заглушек.
*   **Datasheet Intelligence (DI):** Автоматизированное извлечение и структурирование параметров из документации (корпуса, предельные режимы, тепловые данные).
*   **BOM-менеджмент:** Группировка компонентов из схемы, bulk-добавление в корзину, экспорт в CSV/XLSX с привязкой к артикулам и datasheet.

### 4.2. Редактор принципиальных схем и САПР (CAD)
*   **Стандартизация:** Компоненты и условные графические обозначения (УГО) реализованы в соответствии с ГОСТ 2.728-74 и ГОСТ 2.702-2011.
*   **Графический движок:** Ортогональная маршрутизация проводов, автоматическое создание узлов (T-tap), hop-rendering для пересекающихся проводов, антиколлизия подписей (R1, C1).
*   **Функционал:** Поддержка Undo/Redo (50 шагов), экспорт в SPICE-netlist (.cir), PNG, SVG, PDF. Серверная DRC-проверка (Design Rule Check) на наличие висящих выводов, отсутствия GND и коротких замыканий.
*   **CAD-модуль:** Шаблоны ГОСТ 2.104 (А4-А2), библиотека компонентов, штриховки, слои. Поддержка импорта LTspice/SPICE/KiCad subset с предварительным серверным preview и нормализацией в внутренний формат `scheme_data`.

### 4.3. Симулятор и Инженерная аналитика
*   **Браузерная симуляция:** `ngspice.wasm` работает в изолированном Web Worker, не блокируя UI. Поддерживаются анализы: DC/OP, переходные процессы (TRAN), АЧХ/ФЧХ (AC).
*   **Pro-аналитика (Server-side):** Вычислительный кластер на базе NumPy/SciPy/Matplotlib. Реализованы: FFT-спектр, построение диаграмм Боде, статистический анализ Монте-Карло (Monte Carlo tolerance), оценка качества сигнала (THD/SINAD/ENOB), параметрический sweep (What-if).
*   **Fallback-решатель:** Серверный DC-solver на базе NumPy MNA для простых цепей в случае отказа WASM.
*   **Интерфейс аналитика:** Измерительные курсоры (T1/T2), синхронные курсоры по частоте, автоматический расчет -3 дБ полосы, пиковых значений и RMS.

### 4.4. Инженерная лаборатория и База знаний
*   **Структура:** 6 категорий, 21 статья с мультимедийными материалами.
*   **Лаборатория расчетов:** Прикладные узлы (транзисторный ключ, NE555, стабилизатор, RC-антидребезг). Валидация входов через `python-engineering`, символьные вычисления через `SymPy`.
*   **Constraint Solver:** Подбор номиналов с учетом ограничений с использованием SAT-солвера Z3.
*   **Обучающий трек:** Практикум с автопроверкой, использующий реальные ошибки из модуля Engineering Review (Learning-by-review).

## 5. Подсистема искусственного интеллекта и машинного обучения
Архитектура AI построена по принципу «Expert-First», где нейросетевые модели дополняют, но не заменяют инженерные правила.
1.  **Rule AI & Expert Systems:** Версионированные rule packs (`jsonschema`), парсинг SPICE через `Lark`, нечеткая оценка рисков (`scikit-fuzzy`). AI-ассистент формирует ответы на основе топологии, BOM, результатов DRC/ERC и fault-библиотеки.
2.  **Tiny PyTorch Backend:** Легковесная нейронная сеть (фиксированный feature vector по `scheme_data`) для вероятностных подсказок (`deep_hint`) по топологии и следующему компоненту. Обучение на синтетических схемах.
3.  **Engineering Artifact Ingestion:** Парсинг инженерных артефактов (DOCX, PDF, P-CAD DRC/ERC, DXF) для обогащения контекста AI и формирования базы `AITrainingExample`.
4.  **Legal Knowledge Corpus:** Интеграция открытых учебников и официальной документации в качестве evidence-layer для верификации ответов AI.

## 6. Корпоративный контур (Enterprise) и Безопасность
Система поддерживает многопользовательскую работу в рамках организаций (Multi-tenant architecture).
*   **RBAC и Workflow:** 5 ролей (owner, admin, engineer, reviewer, viewer). SOX-style approval workflow (инженер создает -> ревьюер утверждает) с ведением неизменяемого `AuditLog`.
*   **Аутентификация:** 
    *   2FA через `django-otp` (TOTP + backup-коды) с принудительным включением для Enterprise.
    *   SSO через `django-allauth` (Google, Microsoft, GitHub) + Mock-SSO для демо-среды.
*   **Коммуникации:** Приватные беседы команд и публичные Q&A-топики. Realtime-доставка через Django Channels (WebSocket) с автоматическим fallback на AJAX-polling.
*   **Биллинг:** Интеграция со Stripe (Checkout Session, Webhooks) для управления подписками Free/Pro/Enterprise. Поддержка feature-gates для разграничения доступа к Pro-аналитике.

## 7. Инфраструктура, тестирование и мониторинг
*   **Тестирование:** Покрытие кода (pytest + django) составляет ~71% (9969 statements). Реализованы тесты по тирам (Guest, Free, Pro, Enterprise), E2E smoke-тесты (Playwright). Линтинг и форматирование через `ruff`.
*   **Мониторинг (Admin Ops Center):** Интеграция `psutil` для сбора метрик (CPU, RAM, Disk). Централизованный snapshot API для Django Admin. Управление фоновыми задачами обучения ML через модель `MLJob`.
*   **Развертывание:** Локальный запуск через `start_local.bat`, публичное демо — через HTTPS-туннель `ngrok`. Предусмотрена конфигурация для продакшена (Docker, Nginx, Gunicorn, PostgreSQL).
*   **Целостность данных:** Команды `check_demo_ready` и `check_data_integrity` осуществляют комплексный аудит каталога, медиа, демо-схем и стеков научных/экспертных библиотек.

## 8. Эволюция системы (Основные этапы разработки)
Разработка платформы велась итеративно, с последовательным внедрением сложных инженерных стеков:
1.  **Scientific Simulation Stack:** Интеграция NumPy/SciPy для Pro-аналитики и серверных fallback-решателей.
2.  **Lightweight Graph/Formula/SVG Stack:** Внедрение NetworkX, SymPy, Schemdraw для анализа топологии и генерации учебной графики.
3.  **Expert-First Review Stack:** Создание движка правил (Z3, Lark, Pint, scikit-fuzzy) для автоматической верификации схем (Engineering Review).
4.  **Self AI & Artifact Ingestion:** Развитие локального AI-ассистента, парсинг внешних инженерных артефактов, создание корпуса легальных источников.
5.  **Enterprise & Entitlements:** Реализация многопользовательского контура, RBAC, SSO, 2FA и системы разграничения прав (Feature-gates).
6.  **Admin Monitoring & ML Ops:** Создание операционного центра для мониторинга состояния системы и управления задачами машинного обучения.

## 9. Перспективные направления развития
*   **Оптимизация UI/UX и CAD:** Внедрение WebGL/PixiJS для рендеринга схем с 1000+ элементами, расширение библиотеки SPICE-моделей, поддержка импорта/экспорта Gerber и Excellon.
*   **Интерактивная аналитика:** Реализация слайдеров «What-if» с debounced re-run симуляции и live-обновлением графиков.
*   **Расширение AI и 3D:** Интеграция 3D-просмотра печатных плат, диагностика неисправностей на основе AI, расширение лаборатории до полноценного проектного review.
*   **Инфраструктура:** Переход на PostgreSQL, контейнеризация (Docker), настройка Reverse Proxy (Nginx) для production-среды.

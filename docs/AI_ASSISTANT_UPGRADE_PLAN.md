# План: мощное усиление AI-ассистента (синтез §AH+§AI+§AJ)

Синтез ресёрча в один план. Принцип неизменен: **self-hosted, compute-don't-guess** (число —
из движка, не из языковой модели), expert-first с источниками, **клиент-first**. Цель — превратить
ассистента из «шаблон по одному intent» в **агента, который сам собирает многодвижковый
проверяемый ответ**, не теряя анти-галлюцинационность.

## Текущее состояние (проверено по коду)

- `rule_ai` — определяет **один** intent → шаблон + `sections_for_intent` + `build_retrieval_context`
  (грудинг) + session summary + оценка токенов; источники помечаются «источник: …» (expert-first).
- `ai_algorithms` — реестр движков `Algorithm{key,title,intents,run}`: `dc_voltages`, `power`,
  `formula`, `rf_filter`, `tolerance`, `tiny_ai`, **`derating`** (добавлен). `run()` → строки с числами.
- `ai_retrieval` — грудинг из glossary/articles/learning/catalog/legal/training (substring/TF-IDF).
- Движки локальные (MNA, Monte-Carlo, scikit-rf, арифметика, tiny-AI). Внешняя LLM не обязательна.

## Целевая архитектура

```
NL-запрос
  → NLU (intent + эмбеддинги; Transformers.js в браузере, fallback — текущие правила)
  → Планировщик (Plan-then-Execute): какие движки и в каком порядке (мульти-intent)
  → Исполнитель = реестр ai_algorithms (детерминир., не-LLM, параллельно через воркеры)
  → Грудинг + цитаты (ai_retrieval: семантический чанкинг + hybrid + опц. reranker)
  → Ответ с видимым планом (ReAct-трассируемость) + «источник:» на каждом факте
```

## Фазы (приоритет · объём · риск · зависимости)

1. **P1 · M · риск низкий · БЕЗ новых зависимостей — Plan-then-Execute планировщик** (§AI).
   В `rule_ai`/`ai_algorithms`: вместо одного intent — **планировщик выбирает НЕСКОЛЬКО движков**
   под запрос (напр. «проверь LED-цепь» → `[dc_voltages, formula(led), derating, drc]`), исполняет
   через реестр (исполнитель уже есть), собирает **многосекционный** ответ + показывает **план как
   шаги** (трассируемость). Чистый Python над готовым реестром. **Первый шаг — самый дешёвый и
   мощный.**
2. **P2 · M · риск низкий · без/мало зависимостей — качество retrieval** (§AH).
   `ai_retrieval`: **семантический чанкинг** статей знаний (не фикс-размер), **hybrid** (TF-IDF +
   ключевые слова), не перегружать контекст (cliff ~2500 ток), **тегировать цитаты** (откуда факт).
3. **P2–P3 · M · риск средний · НОВЫЙ клиент-ассет — Transformers.js intent-классификатор** (§AJ).
   Малая ONNX-модель классификации в браузере → надёжная NL-классификация intent для планировщика
   (вместо keyword). Self-hosted (статик-ASSET, remote hub off), ленивая загрузка + кэш, WASM-фолбэк.
4. **P3 · M · риск средний — Transformers.js эмбеддинги → клиентский семантический retrieval** (§AJ).
   **Обходит Python-wheel проблему** (fastembed/torch на Windows+py3.14, [[project-semantic-search]]):
   модель в браузере. Семантический поиск без сервера и без pgvector. Опц. cross-encoder reranker.
5. **⏸ post-defense — GNN-инференс в браузере (ONNX)** как нейро-движок реестра (§T) +
   **параллельный запуск** независимых движков через воркеры (§Q).

## Принципы (неизменно)

- **Compute-don't-guess:** число — из движка, «источник:» обязателен. Это анти-галлюцинация **by
  design** — главный тезис защиты против «это ChatGPT придумал».
- **Self-hosted / клиент-first:** всё, что можно, в браузере (Transformers.js/ONNX, движки); сервер —
  обязателен архитектурно, но демо до защиты — на клиенте.
- **Реестр `ai_algorithms` — единая точка расширения:** новый «навык» = новая запись; планировщик и
  NLU работают поверх него, не переписывая ядро.

## Риск-рамки до защиты

- Фазы 1–2 — **безопасны** (Python над готовым реестром, без новых зависимостей) → можно до защиты.
- Фазы 3–4 (Transformers.js) — **новый клиент-ассет + вес модели** → аккуратно, лениво, с фолбэком;
  если рискованно для демо — **после защиты**.
- Фаза 5 — **post-defense**.

## Первый шаг (рекомендация)

**Фаза 1 — планировщик Plan-then-Execute** поверх `sections_for_intent`: мульти-движковый выбор +
видимый план. Без зависимостей, низкий риск, сразу заметное усиление «ассистент сам всё проверил».

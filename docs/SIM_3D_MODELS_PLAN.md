# План: 3D-модели корпусов компонентов (procedural + GLTF)

Дата: 2026-06-13. Цель — довести модели корпусов в 3D-просмотре платы до «нормальных».
Два трека: **A — докрутить процедурные** (быстро, безопасно, до защиты) и **B — реальные GLTF**
(красиво, крупнее, после защиты). Точечные правки — по мере того, как юзер укажет слабые модели.

Файлы: `shop/static/simulation/scheme-3d-components.js` (геометрия), `scheme-3d-materials.js`
(материалы), `scheme-3d.js` (сцена). Диспетчер — `makeForType(comp)`: сначала пакетные модели
(DIP/SOIC/SMD/TO-220/SOT-23/terminal), иначе детальные `makeResistor/LED/Capacitor/Diode/Battery/
IC/Inductor/Transistor/Switch/Ground/Node`, иначе `makeTechnicalFallback`.

Текущее состояние (проверено 3D-смоуком `scripts/smoke_3d_components.py`): модели **не сломаны**,
рендерятся корректно, выглядят прилично, но базово-процедурно.

## Трек A — докрутить процедурные (pre-defense, низкий риск)

Приоритет по «слабости» (что заметнее всего):
1. ✅ **switch** — был коробка+коробка → тактовая кнопка (корпус + металлокрышка + кнопка + 4 пина). Сделано.
2. **inductor** — 5 плоских торусов → настоящая спираль (TubeGeometry по винтовой кривой) на сердечнике.
3. **battery** — простой красный бокс → корпус PP3/9В с этикеткой-обёрткой и двумя кнопочными клеммами (или монетка CR2032 как альт).
4. **makeIC** — насечка сейчас полусфера в углу → центрированная лунка pin-1 + точка-маркер (низкий приоритет: type=ic идёт через `makeChipPackage`, а не `makeIC`).
5. **makeChipPackage** — добавить точку pin-1 (тёмный цилиндрик у первого вывода) и лёгкий фаску корпуса.
6. **resistor** — скруглить торцы корпуса (капсула вместо плоского цилиндра), чуть тоньше выводы.
7. **Материалы (общий проход)** — единые roughness/metalness, мягкие фаски корпусов, аккуратные выводы (`scheme-3d-materials.js`).

Каждый пункт — изолированная функция, регрессий ядра нет. Проверять смоук-скрином после правок.

## Трек B — реальные GLTF-модели (post-defense, главный «вау»)

Механизм УЖЕ есть: `_externalModelUrl(comp)` читает `comp.model_3d_url` / `params.model3d`; затем
`tryAttachExternalModel` грузит `.glb` через `THREE.GLTFLoader`, вписывает в габарит и прячет
процедурный fallback. **GAP-1 (важно):** на странице подключён только `GLTFExporter`, а
**`GLTFLoader` НЕ подключён** (`simulation.html` ~стр.29) → сейчас внешние модели молча не грузятся
(`if (!THREE.GLTFLoader) return false`). Первый шаг трека B — добавить `<script GLTFLoader.js>`.

Шаги:
1. Подключить `GLTFLoader.js` (lib, defer) рядом с `GLTFExporter`.
2. **Библиотека моделей по корпусам** (а не по конкретной детали): `shop/static/models/3d/<package>.glb`
   (DIP-8, SOIC-8, TO-92, TO-220, SOT-23, 0805/0603 chip, radial-cap, LED-5MM, axial-R, terminal-2P…).
3. **Реестр** `package → glb-url` в JS: `_externalModelUrl` резолвит модель по `package_type`
   компонента; нет в реестре → процедурный fallback (уже работает).
4. **Источники ассетов (лицензия — обязательно проверять):**
   - **KiCad packages3D** — официальные STEP-модели корпусов, конвертировать STEP→glb (FreeCAD/
     pythonOCC headless). Лицензия KiCad libs — проверить (CC-BY-SA / отдельная).
   - CC0-библиотеки (Poly Pizza, Sketchfab CC0), параметрическая генерация glb офлайн.
   - НЕ брать GrabCAD/закрытое без лицензии. Хранить `source`+`license` по каждому ассету.
5. Оптимизация: glb с draco-сжатием, низкополигональные LOD (на плате компонентов много).
6. Fallback-стратегия: пока нет glb для пакета — остаётся процедурная модель (Трек A держит планку).

## Точечные правки
Если юзер укажет конкретные «плохие» компоненты — правим их адресно (Трек A), не трогая остальные.

## Порядок
- **До защиты:** Трек A (швейцарский разбор по списку, начиная с inductor/battery) + GAP-1 (подключить
  GLTFLoader, чтобы механизм внешних моделей ожил). Низкий риск.
- **После защиты:** Трек B — библиотека glb по корпусам + реестр + конвейер STEP→glb (часть вектора
  «платы с корпусами» / design+3D).

# План: симулятор → живая CAD-программа

**Создано:** 2026-05-30. До защиты ~3 недели.
**Цель:** превратить визуально-готовый симулятор в **функционально-полноценный CAD** — чтобы каждая кнопка делала что обещает, каждая панель показывала живые данные, и сценарий «нарисовал → запустил → измерил → экспортировал» работал без багов от начала до конца.
**Скоуп:** только редактор схем (`tools/simulation.html` + `Dolg_APP/services/*` + `shop/static/simulation/*.js`). PCB/CAD-страница, AR/3D-overlay, ML-toolbar — не трогаем (это отдельные блоки).

## 2. Core CAD-feel — что делает программу «живой»

### 2.1. Onboarding (1 день)

**Проблема:** новый юзер открывает редактор → пустой канвас, не знает с чего начать.
**Фикс:**
- При первом заходе (без `localStorage.dolg.onboarded`) — overlay с 3 шагами: «1. Кликни Компоненты → выбери Резистор. 2. Кликни на канвасе. 3. Нажми ▶ Запуск.»
- «Загрузить демо-схему» кнопка в hamburger — открывает делитель напряжения или RC-фильтр.
- Tour подсказки через intro.js-like overlay (можно своими CSS).

**Acceptance:** новый юзер без подсказки от научрука собирает делитель за < 60 секунд.

### 2.2. Live-симуляция (1-2 дня)

**Проблема:** Запуск — это всегда DC одного prешета. Нет «непрерывного запуска» для TRAN.
**Фикс:**
- Кнопка «🔴 Live» рядом с ▶ Запуск — каждые 200мс перезапускает симуляцию (как Falstad).
- При изменении любого компонента — авто-перезапуск (debounced 300мс).
- Scope обновляется в realtime.

**Acceptance:** меняю value резистора слайдером — multimeter и scope обновляются без клика «Запуск».

### 2.3. Live-измерения через ПКМ (1 день)

**Проблема:** чтобы измерить — нужно: запустить → открыть Лаб → выбрать узел → читать. Долго.
**Фикс:**
- Hover на узле провода после симуляции → tooltip «1.23 В».
- ПКМ → «Измерить напряжение здесь» → добавляет пин (probe) с visible-меткой прямо на канвасе (как KiCad после `Show Voltages`).

**Acceptance:** ПКМ на узле → числовой бабл рядом с узлом, обновляется при перезапуске.

### 2.4. Drag-and-resize всех панелей (1 день)

**Проблема:** только Лаб-панель ресайзится. Канвас — фикс. Properties-таб — фикс.
**Фикс:**
- Resize-bar между canvas и sim-dock (как у Лаб).
- Resize-bar между left-toolbar и canvas (drag для шире/уже).
- Все сохраняются в localStorage.

**Acceptance:** все панели юзер настраивает под себя.

### 2.5. Component snapping и направляющие (1-2 дня)

**Проблема:** компоненты на канвасе слипаются неровно — нет alignment guides как в Figma.
**Фикс:**
- При drag компонента — показывать **синие линии-направляющие** к X/Y координатам других компонентов.
- Snap на ровные деления grid (5px/10px) обязательный.
- Shift+drag — свободное перемещение без snap.

**Acceptance:** перетягиваю R2 ближе к R1 — на одной горизонтали появляется guide, компонент snap'ается.

### 2.6. Multi-select операции (1 день)

**Проблема:** Drag-select работает (выделение есть в status-bar'е), но действия над группой неполные.
**Фикс:**
- Ctrl+A — выделить всё на текущем листе.
- После drag-select: Delete удаляет всех. Drag перемещает группу. Ctrl+C/Ctrl+V копирует.
- Контекст-меню над группой: «Группировать», «Выровнять по левому/центру», «Распределить».

**Acceptance:** выделяю 4 резистора в делителе → Ctrl+C → Ctrl+V → вставлены копии справа.

### 2.7. Анимации осциллографа + «авария-режим» (1-2 дня)

**Проблема:** scope сейчас — статичная картинка после симуляции. Юзер: «осциллограф должен сбоить при критических значениях». Реальный CRT-прибор показывает дрожание, клиппинг, перегрузку — это часть «живости» CAD.

**Фикс — три эффекта в `drawScope` (scheme-lab.js):**

1. **Phosphor-эффект (по умолчанию)** — после каждого refresh старая волна **fade-out** через `globalAlpha` 0.85 → 0.0 за 4-5 кадров. Создаёт характерный «послесвет» CRT, ~3 FPS sweep visually feels alive. Реализация: requestAnimationFrame loop рисующий с уменьшающейся прозрачностью буфер прошлой волны поверх grid.

2. **Clipping при перенасыщении** — если `|V_max| > range × V/div`:
   - волна обрезается ровно по верхней/нижней границе (squared edges, не sinusoidal)
   - в обрезанных участках добавляется **красная hatch-полоса** (45° штриховка)
   - вверху scope бежит надпись «⚠ OVERFLOW» с мигающим бордюром карточки

3. **Шум/дребезг при критических токах** — если на любом узле детектируется `dV/dt > threshold` (резкий скачок) или `current > 0.95 × max_safe`:
   - волна получает **гауссов шум** ±5% амплитуды (имитация эл. наводки)
   - на грид добавляется **горизонтальный «trace»-сдвиг** (lag-эффект)
   - LED-индикатор «OVERLOAD» рядом с title

4. **Перегрузка компонента** (P_dissipated > comp.power_rating):
   - на канвасе схемы у компонента появляется **анимированный красный halo** (pulse 1Hz)
   - в Лаб у multimeter unit-line меняется на «🔥 OVERHEAT»

**Acceptance:**
- Подаю на 5В-резистор источник 100В → clipping видим, OVERFLOW мигает, R сам пульсирует красным.
- Транзистор в зашкаливающем токе → дребезг волны + LED OVERLOAD.
- Демо-схема (делитель) — никаких эффектов, чистая зелёная волна.

**Размер блока 2:** 8-11 дней суммарно. **Минимум для защиты:** §2.1 + §2.3 + §2.6 + §2.7 (4-5 дней).

## 3. Pro features — для «wow» научнику

### 3.1. Net labels (1 день)
Юзер кликает на провод → присваивает имя «VCC», «OUT». Все провода с тем же именем = тот же net (даже не соединённые визуально). Это **базовая фича KiCad/Eagle**.

### 3.2. Bus connection (2 дня)
Толстый провод как «шина» — несколько net'ов в одном визуальном проводе. Для 8-битных шинных схем.

### 3.3. Hierarchical sheets (2 дня)
«Лист N» как **subcircuit** — рисуешь делитель, сохраняешь как «VoltageDivider.subckt», вставляешь в другие проекты как чёрный ящик с pin'ами.

### 3.4. Cross-probing с симуляцией (1 день)
В Engineering Review кликаю на finding «R5 перегрузка» → канвас подсвечивает R5 + автоматически центрируется на нём.

### 3.5. Импорт KiCad-схемы (3-5 дней)
`.kicad_sch` парсер — реальные схемы из KiCad открываются в DOLG.

### 3.6. Оптимизация контекстного меню + расширяемые компоненты (2-3 дня, запрос юзера 2026-05-30)

**Цели:**
1. **Сократить** ПКМ-меню — сейчас 11+ компонентов + инструменты + операции. Слишком длинный список, прокручивается.
2. **Сгруппировать** в подменю «Добавить → пассивные / активные / источники / прочее».
3. **Расширяемость**: возможность **добавить новый компонент прямо из симуляции** (загрузить через «📦 Каталог» из магазина → новый тип в палитре). Сейчас типы захардкожены в `getComponentPorts`/`getComponentLabel`/`drawComponent` switch'ах.
4. **Реальные элементы из shop**: «🛒 Добавить из магазина» в ПКМ → открыть мини-каталог фильтрованный по типу → выбрать конкретную деталь (например R 100k 1206) → добавить с её spec'ами + ссылкой на product_id.

**Реализация:**
- ПКМ-меню рефакторить на data-driven (массив items с children), а не hardcoded HTML.
- Components-drawer (📦) уже скрыт — его JS-обработчики переиспользовать как back-end для «реальные из магазина».
- Bridge: `addComponentFromCatalog(productId, type, params)` — backend endpoint загружает product → возвращает component-spec → applySchemeData добавляет на канвас.

**Acceptance:** ПКМ → «🛒 Резистор из каталога» → попап с список резисторов из магазина → клик → добавлено с product_id + полным spec'ом, на канвасе видно с конкретным значением номинала.

**Размер блока 3:** 11-16 дней. **Не успеваем все** до защиты — но **§3.1 (net labels) — обязательно**, остальное в Phase 2. §3.6 — хороший wow-эффект для научнику если успеем.

## 6. Acceptance критерии для «оживления»

Чтобы можно было сказать «симулятор стал CAD»:

1. **Демо-сценарий**: пустой канвас → выбрать «Загрузить демо: делитель напряжения» → нажать ▶ Запуск → multimeter показывает 6.0 В → Live-режим на → потянуть слайдер R2 → multimeter обновляется живьём. **Время: < 30 секунд.**
2. **Каждая кнопка** в toolbar делает что обещает, без silent fail'ов.
3. **Hamburger ☰** — каждый пункт открывает то что обещает.
4. **Properties-таб** — клик по компоненту → видны его параметры → редактирование сохраняется → undo откатывает.
5. **Лаб** — после симуляции **все три прибора** показывают живые данные.
6. **DRC** запускается, выдаёт списком ошибок с привязкой к компонентам.
7. **Сохранить → загрузить** — round-trip работает 1:1.

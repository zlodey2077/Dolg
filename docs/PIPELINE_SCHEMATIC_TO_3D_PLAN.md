# План: «Красивая схема → авто-PCB → реалистичный 3D» (вау-вектор к защите)

Стратегия (юзер 2026-06-14): главный вау-эффект — **красиво нарисованная схема, которая
автоматически превращается в плату и эффектно отображается в 3D, как настоящая**. Точность
расчётов проверять будут сильно позже → **визуал и автоматизм приоритетнее точности**.
Ключевая идея: **реюз нетлиста** (связность, та же, что кормит SPICE) как единый мост
схема → симуляция И схема → плата → 3D.

## Что УЖЕ есть (проверено по коду 2026-06-14)

- **Нетлист-мост:** `scheme-netlist.js` (`buildPortNetMap`) + `scheme_connections` в `scheme_data`.
- **Авто-плата:** `services/pcb_layout.compute_pcb_layout(scheme_data)` — расстановка компонентов +
  пады из схемы.
- **Автотрассировка:** `services/autorouter.autoroute_layout(layout, scheme_connections)` — **A* уже
  потребляет нетлист-связность** (это и есть «реюз спайси для роутинга»). Endpoint
  `pcb/<id>/autoroute/`, кнопка в `pcb.html`.
- **3D-плата:** `scheme-3d.js` (+ `scheme-3d-components.js`) — footprints → пады → дорожки (пока
  плоские), реалистичные **корпуса компонентов подняты** (Track A). Материалы PCB (soldermask/ENIG/
  silkscreen) есть в `scheme-3d-materials.js`.
- **Экспорт:** Gerber.zip, GLB, PNG (4 ракурса).

**Вывод:** пайплайн архитектурно собран. Задача — не строить, а **отполировать до «вау»** и убрать
трение (один клик), не трогая то, что и так работает (стабильность к защите).

## Приоритеты (вау / усилие, ранжировано)

1. **🟢 45°/октилинейные трассы** (вместо манхэттена 90°) — §L. Самый большой «выглядит как настоящее»
   за минимум кода: либо octilinear-ходы в A* (разрешить диагонали), либо пост-обработка каждого
   90°-угла в два 45° (chamfer). Серверный (autorouter.py) — но это ключевой визуал PCB.
2. **🟢 Реалистичный 3D-борд:** (а) **env-map** на сцену (§P) — металл/ENIG/эпокси сразу «заиграют»
   отражениями, дёшево; (б) **дорожки как медь с толщиной** (сейчас плоские) + soldermask поверх;
   (в) пады ENIG (материал есть). Клиент (Three.js), изолировано.
3. **🟢 Один клик «Схема → Плата → 3D»:** связать `compute_pcb_layout` → `autoroute` → открыть 3D
   единым действием/мастером, чтобы на демо был «вжух — и плата как настоящая». Снять трение между
   страницами (simulation ↔ pcb ↔ 3D).
4. **🟡 Красивая схема (источник вау):** УГО почище, авто-выравнивание, аккуратные ортопровода с
   узлами (часть есть) — чтобы исходная схема выглядела «учебниково».
5. **🟡 3D-полировка:** silkscreen-подписи (R1/C1) на плате, GND-полигон заливкой, фаски платы,
   мягкая тень/блоб (§P), авто-вращение для презентации (есть кнопка).
6. **⏸ Потом (после защиты / по времени):** точность расчётов (Newton §W, TRAN §AC, термика §Y),
   DRC по правилам (§N/§AB), Gerber-точность, серверный масштаб (Xyce).

## Принципы исполнения

- **Стабильность демо > новые фичи**: не ломать рабочий редактор; правки изолировать (3D-оверлей,
  autorouter-сервис, отдельные кнопки).
- **Реюз нетлиста везде**: один источник связности (`scheme_connections`) → и sim, и ratsnest, и
  autoroute. Не дублировать.
- **Клиент до защиты**: 45°-пост-обработку и 3D-полировку можно держать клиентски; серверный autorouter
  трогаем точечно (только octilinear/chamfer).
- **Проверка скринами**: каждый визуальный шаг — через `scripts/smoke_3d_components.py`-подобный
  прогон (WebGL рендерится headless, проверено).

## Первый шаг (когда скажешь «в код»)

**№1 — 45°-трассы**: добавить в `autoroute_layout` пост-обработку traces (90° → два 45°/дуга) ИЛИ
octilinear-соседей в A*. Затем **№2а env-map** для 3D. Оба — заметный визуальный скачок «как настоящее»
за малый риск.
